## 1. Purpose and scope

This plan sets how your existing records move into MDARIX with the MDARIX import, and how you will show that they
arrived complete and correct. It covers the import of files (CSV or Excel) through the import screen. It does not
cover a live connector to your QMS, which is set up and tested separately.

How the MDARIX import works, in short:
- An import is all or nothing, unless the uploader chooses to set problem rows aside; a failed run saves nothing
  (`backend/app/data_import_router.py:171-177`).
- A row that fails a check is set aside (quarantine) with its reasons; it can be corrected and imported again, or
  dismissed with a reason (`backend/app/data_import_router.py:310-395`; requirement REQ-IMP-001).
- A row that suggests harm to a person reaches triage also while it is set aside (`backend/app/import_quarantine.py:9,39-40`;
  requirement REQ-IMP-003).
- Each run keeps a data-quality report: rows read, accepted, set aside, new, changed and unchanged, and whether the
  counts balance (`backend/app/trial/imports.py:2073-2109`), readable later per run
  (`backend/app/data_import_router.py:456-494`).
- Each imported row keeps its lineage: the run, the file line and the mapping version
  (`backend/app/import_lineage.py:19`; `backend/app/data_import_router.py:397`).

## 3. Rules

- **MIG-R01** This plan shall be approved by your QA before the first import into a live organisation.
- **MIG-R02** Each source system shall have its record count taken at extraction and recorded in section 4.
- **MIG-R03** Each import shall first be run as a check (the import's check step) and its problems resolved or
  accepted in writing before the run.
- **MIG-R04** The template and mapping version of every run shall be recorded (section 5).
- **MIG-R05** For each run, rows read shall equal rows accepted plus rows set aside (the report's "balanced" is true).
- **MIG-R06** Every row set aside shall end corrected and imported, or dismissed with a reason, before go-live.
- **MIG-R07** Every row that suggests harm shall be reviewed by the triage reviewer, whether imported or set aside;
  it shall not be sampled.
- **MIG-R08** The sample verification of section 8 shall be done by a person other than the one who ran the import.
- **MIG-R09** Real personal data shall be imported only when your procedure and your contract with MDARIX allow it;
  otherwise the import masks it (the uploader's masking choice is recorded with the run).
- **MIG-R10** The migration report (MDX-CUS-003) shall be approved by your QA before go-live.

## 8. Verification

### 8.1 The seven interface checks

MDARIX tests the import interface for each release against these seven checks (MDX-VAL-001 Annex F,
`docs/validation/MDX-VAL-001_VALIDATION_MASTER_PLAN.md:589-611`). Your migration checks the same seven properties
on your data.

| Check | What you verify on your data | Method | Result |
|---|---|---|---|
| Accuracy | Values arrive as in the source, characters included | Sample of section 8.2 | |
| Completeness | Source count = rows read; rows read = accepted + set aside | Counts of section 4 and each run report | |
| Consistency | The same record imported twice gives one record, not two (requirement REQ-IMP-002) | Re-import one sample file into the UAT organisation | |
| Transformation and rounding | Dates, time zones, yes/no columns and codes become the right MDARIX values | Sample of section 8.2, every date column | |
| Sequence | Follow-up records (lots after products, Cases after products) load after the records they need | Run order of section 5 | |
| Duplicates | No duplicate complaint is created by a re-upload | Run report: new / changed / unchanged counts | |
| Failure recovery | A failed run saves nothing; a set-aside row can be corrected and imported | One deliberate failing file in the UAT organisation | |

## 9. Rollback

MDARIX has no function that undoes a completed import run: the import routes are check, run, quarantine, lineage and
run reports (`backend/app/data_import_router.py:227-509`). Plan your rollback accordingly:

- **MIG-R11** The first import of each template shall run in the UAT organisation (MDX-CUS-001 UAT-R07) before the
  live organisation.
- **MIG-R12** A wrong value found after a live run shall be corrected in MDARIX with a reason, audited, or by a
  re-upload where the template allows it (section 7); it shall be logged as a deviation.
- **MIG-R13** If a live run is wrong as a whole, your QA shall decide in writing, with MDARIX, before any further
  import.
